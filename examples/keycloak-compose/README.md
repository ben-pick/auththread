# Keycloak example

No cloud account and no Auth0 tenant. Keycloak, the stitcher, an OTel collector and Grafana
run in one compose file.

```sh
pnpm install
pnpm --filter @auththread/example-keycloak build
docker compose -f examples/keycloak-compose/docker-compose.yml up --build
```

Then:

1. Open http://localhost:8080 and sign in as `demo` with password `demo`.
2. Read the wide event with `docker compose -f examples/keycloak-compose/docker-compose.yml logs stitcher | grep auth.journey`.
3. Open http://localhost:3000, pick the Tempo data source, and search for service `auththread` to
   see the same journey as a trace.

The failures to try: press Sign in and stop at the Keycloak form (abandoned), and sign in
with a wrong password (failed). Both produce a journey.

**Log pipeline gap.** The compose sends spans over OTLP to the collector, so Tempo works. The
wide event is written to the stitcher's stdout, and this compose has no log shipper, so it
does not reach Loki. Add Vector or Fluent Bit, or point a Loki sink at the stitcher, before
using the Loki dashboard.

`web/app.js` is generated by `pnpm --filter @auththread/example-keycloak build` and is
ignored by git. The build fails if the minified browser bundle exceeds 5 KB gzipped.

This compose file was not executed in the environment where v0.1 was built, because Docker
was unavailable there. The bundle budget and the TypeScript do run in `pnpm check`.
